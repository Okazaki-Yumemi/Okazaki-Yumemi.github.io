【暂时AIGC占位】DesktopManager：桌面上的东西，能不能各归各位

发表于2026-10-11|更新于2026-10-11|项目

桌面上有文件，有快捷方式，也有一些暂时不想处理的东西。

它们待在那里很方便，但方便久了，就会变成另一种不方便。要找的时候得扫一遍；想整理的时候，又担心改动原来的位置之后，之前的路径和习惯都乱了。

DesktopManager 把“整理”先做成了一个单独的层。至少不必为了给文件分组，就马上把文件搬来搬去。

整理关系，不急着整理磁盘

虚拟集合保存的是文件与集合的关联，而不是把原文件实际移动到新目录。桌面索引负责发现和记录对象，集合负责提供另一个观察方式。

这样做并不意味着磁盘从此就不需要整理了。它只是把“我现在想把这些东西看作一组”和“我要改变它们的实际位置”分开。

这个区别很小，却能少一点顾虑。

界面后面也要分层

项目使用 Tauri 2、Rust、Svelte 5 / TypeScript 和 SQLite。界面经过统一的调用入口进入 Tauri commands，继续交给领域逻辑和存储层；SQL 留在存储模块中，Windows 桌面相关行为则放在专门的适配模块。

看起来绕了几层，但每层有自己的职责。界面不需要知道一条查询怎么写，数据库也不应该决定一个按钮长什么样。

仓库还记录了桌面监听、布局快照、工作场景、任务、日历、专注计时及日历导出等功能。它开始不只是一个文件列表，而是在尝试把工作时会一起出现的东西放在同一个地方。

能跑，和放心使用之间

这类工具的难点，经常不在演示最顺利的那一条路径。

文件消失了怎么办？数据库升级失败怎么办？重启之后，刚才的计时还在不在？显示器和 DPI 变了，原来的布局还能不能用？这些问题都比再加一个按钮更实在。

架构文档里有迁移备份、缺失文件标记等处理；状态记录也区分了自动测试、浏览器检查和真实 Windows 窗口验收。这里按这些公开记录介绍功能，不把所有功能都写成已经逐项实机验证，更不补上没有依据的性能承诺。

一个桌面工具最终还是得回到日常使用。希望整理完之后，事情真的少一点，而不是又多出一个需要整理的软件。
