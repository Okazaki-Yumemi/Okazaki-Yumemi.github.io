# BTC-LLM Efficient Sub-1Bit LLM Quantization via Learnable Transformation and Binary Codebook

这篇相比于前面几篇，有一个更夸张的想法。 —— 已经是 1-bit的 Binary Weights , 能不能继续压缩到1bit下？

# Abstract
1. motivation: 为什么1bit还不够?
Binary Quantization 是一种非常激进的压缩方式 W -> B, 原本每个权重需要FP16的 16bit，现在只用一个 1bit的值来表示符号。

然而作者认为 即使模型已经被压缩到了1bit,但是仍然存在着继续减少存储成本的机会。

过去有人尝试过稀疏化方法实现 sub-1-bit，例如STBLLM，但是作者认为，这种方式存在三个问题
1. 精度损失
2. 稀疏Mask的存储和管理开销
3. 部分硬件上面难以高效执行。

所以BTC-LLM给自己定的一个目标是在不依赖系数Mask的情况下，将Binary Weights 进一步压缩至 1-bit以下，并保持模型精度和执行效率。

2. 第一项贡献: Binary Codebook
对于一个binary weight Matrix，每个权重只有1bit了，为什么还有可能继续压缩？答案是: 不同的二值向量模式可能重复出现，而且分布可能非常不均匀。

例如10个权重，现在0 or 1 我们可能需要用10bit去存储，不过假设我们把二值权重划分成长度为10的向量。理论上有1024种方式。

但假设实际出现的向量高度集中在一部分模式附近，我们可能只需要维护512个代表性的codewords，那么就只需要 log2(512) = 9 bit

所以，**BTC LLM 并不是让单个二值权重变得比1bit还小，而是把多个Binary Weights 联合编码，通过模式复用降低平均存储成本。**

这其实就是把vector quantizaiton的思想应用到binary space里面。 不过这也导致了一个新的问题: 直接减少codebook里面的codewords，一些原本存在的二值模式就无法被精确表示了。必须映射到相似的模式。

所以codebook compression 本身也会引入额外的量化误差。这就需要第二个来缓解。

3. 第二项贡献 Learnable Transformation
作者发现，直接进行Binary Quantization 还面临Activation Outliers 的问题.

即使我们权重量化误差相同，Activation Magnitude 较大的方向也可能产生更大的输出误差。于是作者提出:
**能不能在二值化前，先变换权重和激活的表示空间，让权重更容易二值化，同时降低Activation Outlier的影响?**

BTC-LLM使用一个可学习的可逆变换， T= D+-P

其中
- D+-: 逐通道符号翻转矩阵
- P: 可学习的可逆变换矩阵

这个变换希望同时实现两件事情， 降低量化敏感性和增加Binary Pattern Redundancy,使得变换后的二值权重更容易被较小的codebook表达。


# Introduction

1. 现有sub-1-bit路线的不足
STBLLM 通过 N:M Structured Sparsity,从 Binary Weights 中进一步移除一部分权重。
例如采用 2:4 Sparsity，一个包含四个权重的block只保留两个非0值，直观上只有两个非0，每个权重1bit，似乎只需要 0.5bit，但是我们还需要知道哪两个位置是非0的，从四个位置选2个是C42，等于6，所以至少需要3bit进行Mask的表示。

这样，我们最后的BPW反而是1.25! 单纯减少非0权重数量，并不代表实际存储量可以按照比例下降。

## Observation 1: Binary Weights 存在可压缩的重复模式

作者发现，不是所有的符号组合都是等概率出现的，而使一些Binary Patterns更常见。因此存在这样的可能性: 把原本分散的1024种模式，用更少的codewords进行近似表示。

这里隐含了一个假设:
> 二值权重的局部符号模式具有足够的统计冗余，可以在比1 BPW 更低的存储预算被有效的近似。

## Observation 2: 二值化造成的Activation Outliers
在进行表示的时候，先前的二值化表达都出现了很明显的outlier.

在作者提供的数据下，LLaMA-2-7B 中 self_attn.k_proj 的 Activation Distribution 有这样的一个数据
| 方法 | 图中最大绝对值|
|------|--------------|
|FP16 | 8|
|BiLLM|15|
|ARB-LLM| 10|
|BTC-LLM| 0.4|

作者没有直接给出原因，不过可以猜测是由于二值化极端的表达，导致有些激活刚好让他们激活的全部都是1所在的位置，导致产生了非常离谱的输出。

## Research Questions
分析完了问题，我们现在明确知道作者大概想要研究两个问题

- RQ1: 如何不依赖Sparsity，实现Sub-1-bit?
Binary Codebook，通过将二值权重分组成向量，再映射到有限的Codewords,用更短的Index表示多个Binary Weights

这个问题就是为了解决Representation 和 Storage Efficiency问题

- RQ2: 如何让极低Bit CodeBook 保持足够好的模型精度
Learnable Transformation

作者希望通过学习变换矩阵，来减少outliers， 促进权重符号模式的聚集， 降低Binary Codebook 近似产生的误差。

# Section 3 : Preliminary

作者首先采用了 ARB-LLM 一类的二值化表示:

 W ≈ α B + μ
其中
- B 是二值权重矩阵
- α 是逐行Scaling Factor
- μ 进行逐行bias

这部分没有太多新的东西，对于去中心化的权重，二值化近似可以采用 B = sign(W)

# Section 4 Binary Codebook

这部分的核心想法就是把二值权重切开成长度为v的向量
bi ∈ {-1 ， +1}
然后利用binary K-means 找到c个代表性的Codewords

1. 为什么binary K-means 更容易实现?
对于二值向量来说不需要真正做FP32距离计算，可以用汉明距离+类似处理。

2. 存储

M_codebook = vc + log2c nm/v

假设matrix有 nm个元素，第一项是codebook,第二项是index

忽略其他元数据的时候，那么BPW 约等于 log2c/v

所以真正的压缩收益来源于用一个 16-bit Index 代表20个Binary Weights，这是一种有损的联合编码，并非把原本的20-bit模式无损压缩成16-bit

# Section4 Learnable Transformation

作者先引入了等价变换

Y = XWT = (XT)(T-1WT)

其中 T = D P

作者不知识希望降低activation outliers,还希望变换后的binary weight patterns更容易聚类。

所以这个变换不仅优化量化误差，还主动优化权重表示的可压缩性。

# LUT-GEMM: 避免解压codebook

一般来说，量化之后使用的做法是根据index恢复对应向量权重，再执行dot product。 作者提出预先计算 LUTj[k] = xTj ck

那么原来的大量乘加运算就变成了查表和累加。

但是LUT不是完全免费的，构建LUT，随机访问和cache命中率都会影响真实性能。

# 方法论的总结
作者逼逼赖赖了十几页，其实他的一个核心的思想就是什么呢？

就是构建一个类似于字典的玩意嘛！

他都说了，由于二值表现可能性其实没有那么多，那么就有可能出现一个什么事情呢，有两组不同的参数最后的二值表示是一样的，那我们就存其中一种就行了嘛！

举一个极端例子，就是现在某一层里面，我们假设所有的参数都是一模一样的，那我们甚至都只需要一个存储的方式!

例如现在的权重是 [+1,-1,+1,-1] * 4 , 那么我们就存:
[+,-,+,-] , Index = [0,0,0,0] 就好了。

不过作者额外用的一个方法就是稍微对这些权重做了一个聚类，让他们都映射到了一个代表性的codeword，不过注意这个地方就不是无损的咯。

然后learnable transformation相当于就是主动制造更加容易压缩的二值模式。所以我说有点像拼豆有人懂吗？降低分辨率换取好拼。

# 总结

Binary Pattern Redundancy 真实可用。 通过有损 Codebook 编码，可以把二值权重进一步压缩至 Sub-1-bit，并在 0.9-bit 附近保持较好的 PPL。

Representation Transformation 很重要。 在极低比特下，主动优化权重的符号分布，比仅对已有二值权重做聚类更有效。

压缩率和质量存在明显拐点。 0.9-bit 到 0.7-bit 并非平滑无损下降，而且更大的 Codebook 与特定布局也会带来执行代价。
