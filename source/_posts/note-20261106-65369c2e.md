# KBVQ-MoE: KLT-guided SVD with Bias-Corrected Vector Quantization for MoE Large Language Models

TL;DR:

1. 作者认为，Expert之间存在大量的冗余
如果多个expert具有相似的权重表示，我们不应该反复用有限的量化资源去表示这些相似内容。

2. 量化误差不仅会影响权重，还会导致输出分布偏移

因此，作者提出的设计是:

1. 原始Expert权重 We
2. IDRE: KLT-guided SVD  提取跨Expert共享的低秩表示
3. Shared Part -> 保持FP16  Specific Residual -> 进行Vector Quantization
4. BCOS: Bias Correction 对量化输出进行逐通道缩放和偏置校正

**先把重要的共享结构提取出来，只量化剩余的expert-specific Residual 最后矫正量化造成的输出偏差**

# Abstract

Why Vector Quantization?

我们之前看的AWQ和 BitsMoE 主要讨论的是Scalar Quantization

1. Scalar Quantization
scalar quantization 就是根据每个group的值分别映射到一个离散的量化级别，每个权重独立选择对应的整数编码，问题是2-bit的表达能力十分有限，可能导致严重的信息缺失。

2. Vector Quantization
VQ是把多个权重组合成一个向量，然后构造一个Codebook，量化就是选择最接近的Codeword。

其最终存储的主要是 Codeword Index ， 而不是四个权重各自的量化值。 例如 Codebook有256个4维向量，每个向量只需要8-bit index，那么在忽略Codebook和其他元数据开销的时候，每个权重只需要2bits.

所以VQ的优势就相当于是，其利用向量去拟合，而不是每一个小小的值。在同样的Bit Budget 下，使用更有表达能力的向量表示

3. 为什么不能直接给VQ 用在 MoE 上？

- Obstacle 1: 跨Expert的冗余表示

如果两个expert内部存在相似的权重结构，那么如果对整个W1，W2做VQ，就需要在两个expert的量化中反复处理类似的共享结构。所以，作者希望能够献给共同的w提取出来，再将VQ集中用在ΔW里面。
这个和BitsMoE的跨Expert共享思想有类似的地方，但是KBVQ-MoE 更明确的把权重分成了共享部分和待量化的残差部分。

- Obstacle 2: 输出分布偏移

作者认为量化后的输出 y^{hat} = W^{hat} x 和原本的 y = Wx 不仅仅在具体数值上不同，还可能有不同的Mean和 Variance， 如果这种偏差经过多个MoE LAYER 持续传播，模型性能可能严重下降。

因此，作者对提出的量化做 channel-wise Affine Correction，目标就是让校正后的输出统计特征更接近原始FP16模型。

# Introduction

Introduction里面的东西主要的就是为了证明Expert的荣誉确实存在，且IDRE能够提取部分的共享结构。

并且，作者也说了 直接使用VQ之后，部分通道的方差和FP16相比差距较大。而经过KBVQ-MoE 之后，这种差距有所减小。

Introduction后，作者提出了两个核心的方法。

| | IDRE | BCOS |
|-| -----|------|
|全程| Input-driven Redundancy Elimination | Bias-Corrected Output Stabilization|
|问题| Expert 间冗余浪费量化表示能力 | 量化后输出分布差异|
|核心技术| KLT-guided SVD | Vector Quantization + Affine Correction |
| 主要操作| 提取共享低rank结构，保留FP16 | 量化残差，匹配逐通道输出统计 |
| 所处阶段 | 离线权重分解 | 离线校准与在线矫正 |

这里最值得研究的是KLT为什么要放在SVD前面，刚刚读了BitsMoE, 我们已经知道联合SVD可以提取多个expert的共享谱方向。但是KBVQ-MoE 认为，仅仅对Weight进行SVD还不够，因为我们还要考虑Output的关系。

所以作者希望先通过KLT把Input Activation Statistics 融入权重的表示空间，再使用SVD提取共享结构。

所以其实还是利用SVD，不过这里是输出aware 的svd

# Methodology

## 4.1 Input Driven Redundancy Elimination

首先一个共同的常识就是不对所有的expert做SVD，我们至少都是说要把他们放到一起，再进行联合SVD去寻找共享谱空间。

但是KBVQ-MoE 认为: 直接对Weight 做 SVD， 未必能够对模型实际输出最重要的共享方向。

原因就是我们提到的，Bits-MoE 还是局限在静态的对weights进行分解，而没有考虑输出。所以KBVQ-MoE 希望SVD优先保留那些在实际输出分布下，对输出影响较大的方向。

**2.2 KLT:把输入统计引入权重表示**:
论文首先收集输入Activation  X

然后计算 C_x = 1/(B-1) X^TX

然后做特征值分解 C_x = U_klt A U_kltT

再构造 T = U_kltA^(1/2)。

因为Cx = TT^T, 所以在原空间衡量Output MSE ，等价于KLT加权后的空间中衡量 Weight Frobenius Error。 因此我们可以先变换权重，然后对这些变换后的矩阵做SVD

**联合SVD**

方法还是和之前的差不多，不过这次我们衡量的是变换之后的，隐含着输入信息的输出。最后只量化低秩子空间因子B_share

然后他们还是给Shared Part保持了FP16。因为他们认为这个是多个expert重要的共享结构，因为他们被反复使用。

## 4.2 Bias Corrected Output Stabiliation

回到这里，IDRE已经把权重拆开成了两个部分 We = We,share + R_e

接下来就进入BCOS

### 1.先对Residual 进行 Vector Quantization

作者把Re切开成长度为d的小向量，使用K-means 训练code book，对每个向量求最小误差的 Codeword。

普通的VQ是把所有的权重都进行VQ分解，而KBVQ-MoE 是保留share的 We, 只量化没有被shared Part表达的内容。

### 2. Why Bias Correction

即使我们已经保留了重要的共享结构，残差仍然会存在VQ误差，这会导致输出的误差，而且作者认为这种误差会改变每个输出通道里面的均值和方差并在多层模型中积累。于是，他们提出了 y_corr = (1 +s) dot y_hat + b

对于输出通道，定义 aj = 1 + sj, 根据元模型和量化模型的输出统计量，选择 aj = σyj / σy_hat j ， b = μyj - ajμyhatj

如果统计量是准确的，那么残差和均值应该相同，经过矫正之后，每个通道的均值和方差可以和FP16输出匹配。


总结呢，bitsMoE 主要在研究如何分配量化精度，而KBVQMoE 则在研究应该先保留什么结构，量化什么残差以及如何修正量化后的输出。

- KLT-guided 找到的子空间是输入加权意义的子空间，能否泛用出去？
- Shared Part为FP16并不是免费的，他们虽然是低rank表示，但是还是很贵的
